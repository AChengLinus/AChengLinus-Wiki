### [研究者称 GPT-6 Astra 直接改写模型权重](https://rikiyat.github.io/blog/weight-space-programming/) `#1`
> MIT 研究者称，**GPT-6 Astra** 能直接改写神经网络权重，无需训练或梯度。它用练习题进行最多 **50 次**批量测试后，修改 `Qwen3.5-0.8B` 的 **0.016%** 权重，减少推理循环。作者报告，`MATH-500` 从 **7.9%** 升至 **48.1%**；但对不易循环的 `Gemma`，未见明确提升。

MIT 研究者 **Rikiya Takehi** 等人发布博客，展示他们称为权重空间编程的方法：让 `GPT-6 Astra` 直接检查或改写神经网络中决定计算结果的参数，而不通过训练来调整。

作者报告，在 `Qwen3.5-0.8B` 实验中，`Astra` 获得载入权重的 Python 环境，可用训练集练习题进行最多 **50 次**批量前向测试，但不接触评测题，也不能训练或使用梯度；它修改 **0.016%** 的权重后，`MATH-500` 从 **7.9%** 升至 **48.1%**，`GSM8K` 从 **13.8%** 升至 **67.1%**。

作者将改善归因于减少反复推理却无法作答的循环；对较少循环的 `Gemma 3 270M`，同类编辑未带来明确提升。

### [OpenAI 自研 Git 后端 Pando 投产，中位推送延迟降近 80%](https://openai.com/index/scaling-git-at-openai) `#2`
> **OpenAI** 披露，因 `Codex` 让并发开发规模大增，自研了新的 `Git` 后端 `Pando`。它兼容现有 `Git` 工作流，目前支撑公司单体仓库全部开发，中位推送延迟降低近 **80%**，每天交付近一个 **PB** 的 `Git` 数据。

OpenAI 发文披露，其为单体仓库打造的新 Git 后端 `Pando` 已经投产，目前承载着 OpenAI 单体仓库的全部开发工作，工程师和 agent 无需改变现有 Git 工作流即可使用。

此前随着 `Codex` 让并行开发规模激增，支撑单体仓库的系统从去年年底前后开始跟不上需求，推送和抓取变慢、合并失败，可靠性一度低于 **90%**。

切换到 `Pando` 后，OpenAI 称中位推送延迟降低近 **80%**，合并可靠性得到改善，系统每天交付近一个 PB 的 Git 数据，单小时曾交付超过 **57 TB**。

该项目从启动到投产只用 **10 周**，以 `Rust` 编写，核心设计出自一位工程师、实现交由多个 agent 团队完成，部分 Git 客户端改进已回馈上游。

### [Anthropic Message API 推出 message threads 公测](https://x.com/ClaudeDevs/status/2117332452603527535) `#8`
> Anthropic 的 `Messages API` 公测 `message threads`，开发者不必每轮重发对话。官方称 `Claude Code` 接入后，**50 万至 100 万 token** 请求的首个 token 响应时间中位数缩短约 **35%**。

Anthropic 在 `Messages API` 推出 **message threads** 公开测试版，开发者开启线程后，每轮只需发送新增消息和上一条消息 ID，由服务端缓存对话，无需重复发送全部历史。

Anthropic 称，该功能已接入 `Claude Code`，并对多数 `Claude Code` 用户默认开启；在 **50 万至 100 万 token** 的请求中，收到首个 token 的中位等待时间缩短约 **35%**，长对话中的单个请求大小中位数从约 **800 KB** 降至 **1.8 KB**。

Claude 每轮仍会读取完整对话，因此 token 用量不变，标准 token 费率和现有速率限制继续适用。线程在最后一次请求 **5 分钟**后过期，开发者仍需在应用侧保存对话副本；该功能适用于所有模型，但不支持 `Message Batches` 批处理、token 计数和对话压缩。

### [OpenAI 部署激活分类器，实时拦截模型违规输出](https://alignment.openai.com/training-activation-classifiers/) `#10`
> OpenAI 披露，自 `GPT-5.6` 起在前沿模型的内部和外部流量中部署激活分类器，利用模型内部信号检测可能违规的回答，必要时中途暂停并交由推理模型复审。OpenAI 称，测试中它比文本分类器更能抵抗越狱攻击。

**OpenAI** 介绍了激活分类器的训练与部署方法，并表示从 `GPT-5.6` 开始，这类分类器已用于监测所有助手回复，作为现有文本分类器之外的一层安全防线。

激活分类器也称为探针，是读取模型内部神经模式的轻量级机器学习模型，用于判断模型活动是否失准或违反政策；目前已部署于 **OpenAI** 能力最强模型的内部和外部流量中。

**OpenAI** 称，探针可在违规回复输出过程中拦截内容，并将消息交由推理模型做最终判定；在红队测试中，探针对越狱攻击总体比基于内容的分类器更鲁棒。

探针依赖标注训练数据，只能检测已知、可测量的不良活动，针对每个新的预训练基础模型都需要重新训练。
