### [Codex WebSocket 请求上限提至 128 MB](https://x.com/charliermarsh/status/2123849871480463669) `#8`
> Codex 发布更新，将模型请求的 WebSocket 大小上限从 **16 MB** 提高到 **128 MB**，整体 HTTP 回退率降低约 **20%**。若请求仍超限，服务器会立即告知客户端，速度提升约 **5 倍**。

**OpenAI** 团队成员 **Charlie Marsh** 发文称，`Codex` 已将模型请求的 `WebSocket` 大小上限从 **16 MB** 提高到 **128 MB**，让大型轮次不再回退到 `HTTP`，整体 `HTTP` 回退率降低约 **20%**。

他表示这个数字相当可观，因为统计口径覆盖连接失败、超时等所有回退原因。

此前请求一旦超限，客户端要先把大部分内容传完，才会被服务器拒绝并重试，之后还会一直卡在不支持增量发送的 `HTTP` 上。

现在服务器会在请求超限时立即告知客户端，跳过这些无效的上传和重试，处理速度提升约 **5 倍**。

### [OpenAI API 为 GPT-6.2 启用跨轮推理复用](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged) `#9`
> **OpenAI** 宣布，`Responses API` 中使用 `GPT-6.2` 的 `Agent` 可跨轮复用推理，以降低 `token` 消耗并提升缓存命中率。

**OpenAI** 宣布，在 `Responses API` 中使用 `GPT-6.2` 的 Agent 可跨轮复用推理，以减少 token 消耗并提升缓存命中率。

从最新前沿模型起，每段推理均与前置对话绑定，若缩短工具输出、改写提示词或直接修改请求参数导致前缀变化，API 将丢弃后续推理，进而推高成本与延迟。

为此，**OpenAI** 新增 `input_transformations` 对象及 Usage dashboard 中的 Reasoning removals 面板，协助开发者排查异常移除，并建议保持对话前缀不变，采用追加方式更新上下文。
